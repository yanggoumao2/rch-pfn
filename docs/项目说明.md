# PFN 研究项目说明

项目主目录在工作站：`/home/yxy/data/projects/rch-pfn`。
本机同名工作区是源码编辑与交付镜像，不承担训练。

这套代码围绕原来的主线实现：从原始图像、已执行动作、机器人状态和已到达结果
形成对象关系证据；共享核心先提出联合解释，再按每种解释对同一段历史重新读取；
输出联合状态分布，并预测候选动作后果。10°只属于以往的讲解例子，不是写入模型的答案。

| 需要修改什么 | 修改入口 |
|---|---|
| 模型层数、宽度、槽数、模式数、协方差秩 | `configs/*.yaml` 的 model |
| 数据范围、对象数量、扰动概率、系统数量 | prior 配置及 `data/` 生成器 |
| 真实仿真或传感记录 | `data/` 的标准 NPZ 导入/导出接口 |
| 训练预算、优化器、损失权重 | train 配置 |
| 模型核心/历史重解释机制 | `model.py` |
| 目标分布和评分方法 | `losses.py` 与 `schema.py` |
| 推理和在线历史追加 | `inference.py` |
| IK、碰撞检查、机器人接口 | `control.py` 的依赖注入协议 |

数据输入与特权监督分开存储。模型输入类型中没有真实故障、隐藏位姿、干预角度或未来结果。
训练/验证/测试按完整系统划分，不能将同一轨迹的相邻窗口分到两边。
数据文件和模型保存都有配置、版本及哈希；恢复训练会拒绝来源不一致的运行。

当前提供完整可运行的训练工程和程序化图像数据管线。该生成器不模拟真实接触物理，
也不能代替之前选定的 LabUtopia 数据。后续研究训练要通过导入接口接入真实仿真记录，
再进行多种子和强基线比较。具体采集方案见 [EXPERIMENTS.md](EXPERIMENTS.md)。

已有 PFN 预训练权重不能简单塞进当前网络：已核对的 TabPFN-3.5 ICL 核心内部宽度为1024，
这里的完整配置为256，归一化和注意力结构也有差别。因此交付明确区分当前自有核心的
先验训练/后训练，与尚需单独实现和验证的官方权重迁移实验。

代码测试通过能说明被检查的性质成立，不能保证永远没有错误，也不等于证明创新有效。
最新实际结果集中在 [VERIFICATION.md](VERIFICATION.md)，原设计与实现的差异集中在
[DESIGN.md](DESIGN.md)。这样以后调整时，不会把设计承诺、程序功能和论文证据混在一起。
